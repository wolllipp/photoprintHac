# picPac One

**Одна система от фото клиента до решения руководителя.**

Проект команды для Space Hackathon с «Великим камнем» и ООО «Фотопринт» (сервис [picPac.by](https://picpac.by)), 11–13 ноября 2026. Закрываем все три трека хакатона одной связанной системой, а не тремя отдельными прототипами.

## Суть

| Часть | Трек | Что делает |
|---|---|---|
| **picPac** — приложение и сайт для клиентов | 2. Мобильный канал заказа | Собирает фотокнигу сама: из фото в телефоне или по описанию словами. Проверяет качество и обрезку лиц до оплаты. Показывает, на каком этапе заказ. |
| **picPac Insight** — данные и дашборд | 1. Управленческая платформа | Связывает финансы, клиентов, производство и кадры. Находит отклонение, показывает его причину и фиксирует решение с ответственным и сроком. Проверяет по данным, помогло ли решение. |
| **picPac Ассистент** — AI-помощник | 3. Защищённый AI-помощник | Отвечает руководителю на вопросы о бизнесе со ссылками на источники, готовит встречи по отклонениям, ведёт протокол и задачи. Тот же движок в роли «клиент» отвечает покупателям круглосуточно — без доступа к данным компании. |

Приложение и ассистент связаны через сервер: `GET /insight/data` отдаёт демо-историю компании и живые заказы и обращения из приложения (ассистент: «что с заказами из приложения?»). Дашборд пока читает ту же демо-историю из своего файла. Заказ из приложения попадает в аналитику, отклонение разбирает ассистент, решение становится задачей, а его эффект проверяется по тем же данным. **Весь AI работает в локальном контуре:** фото клиентов и данные компании не уходят во внешние сервисы.

## Запуск демо (≈15 минут)

Нужны: Docker, [uv](https://docs.astral.sh/uv/), Node 20+, Python 3.12, телефон с Expo Go в той же Wi‑Fi сети. Всё на тестовых данных.

```bash
# 1. Сервер приложения (трек 2): база, миграции, каталог с ценами super.picpac.by
cd services/api && cp .env.example .env               # стенд показа: DEMO_MODE=true (код 0000, /dev/*)
uv run python -c "import secrets; print('JWT_SECRET=' + secrets.token_urlsafe(48))" >> .env   # свой секрет, без него сервер не стартует
docker compose up -d                                   # PostgreSQL + pgvector на :5433
uv sync && uv run alembic upgrade head && uv run python -m app.seed
uv run uvicorn app.main:app --host 0.0.0.0 --port 8000  # http://localhost:8000/docs

# 1а. Модель для «ИИ: исправить» (понимает замечания в редакторе) — в новом окне. Без неё работают правила.
#     Ollama: ollama serve, затем ollama pull qwen2.5:3b (EDIT_MODEL; ~2 ГБ, ответ ~1 с на процессоре).
#     Если ollama pull падает с «resolves to non-public» (VPN с подменой адресов, например Clash в режиме fake-ip):
#     скачать qwen2.5-3b-instruct-q4_k_m.gguf с huggingface.co/Qwen/Qwen2.5-3B-Instruct-GGUF и
#     ollama create qwen2.5:3b -f Modelfile (FROM ./qwen2.5-3b-instruct-q4_k_m.gguf + шаблон ChatML Qwen).
#     Голос → текст (POST /speech) — Whisper внутри сервера, модель скачается сама при первом запросе (~460 МБ).

# 2. Приложение клиента (трек 2) — в новом окне
cd apps/mobile && npm install && npx expo start         # отсканировать QR в Expo Go
# адрес сервера приложение берёт само (тот же компьютер, порт 8000); иначе EXPO_PUBLIC_API_URL=http://<ip>:8000

# 3. Ассистент руководителя (трек 3) — в новом окне; модель локальная
brew install ollama && ollama serve & ollama pull qwen3:4b-instruct
cd services/assistant && uv sync
ASSISTANT_DATA_URL=http://localhost:8000/insight/data uv run uvicorn app.server:app --port 8001   # данные компании + живые заказы и обращения из приложения

# 4. Дашборд Insight (трек 1) + экран «Ассистент» — в новом окне
python3 -m http.server 8080 --directory design/insight  # http://localhost:8080

# 5. Ассистент отдельной страницей в стиле приложения (трек 3) — в новом окне
python3 -m http.server 8090 --directory design/assistant  # http://localhost:8090 (другой адрес сервиса: ?api=http://host:8001)
```

**Тестовые учётные записи и роли**
| Где | Как войти |
|---|---|
| Приложение | гость без входа; при оплате — свой номер телефона и код из SMS `0000` (только при `DEMO_MODE=true`; без него вход по SMS выключен). Разные номера — разные аккаунты. Демо-аккаунт с 350 пиками — `+375 29 700-00-00` (создаёт `app.seed` при `DEMO_MODE=true`). Оплата не списывается |
| Дашборд и ассистент | переключатель роли в интерфейсе: «Руководитель» (`ceo`) и «Менеджер» (`manager`, без кадровых показателей); `admin` ассистент отклоняет |
| Сотрудник (менеджер) | `+375 29 700-00-01`, код `0000` (создаёт `app.seed` при `DEMO_MODE=true`): журнал действий `GET /admin/audit` и все заказы `GET /admin/orders` в `http://localhost:8000/docs`. Клиенту и гостю сервер отвечает 403 |
| Демо статуса заказа | `POST /dev/orders/{id}/advance` двигает заказ по этапам |

Обязательный путь клиента (ТЗ, 6.2): «+» → «Из фото» → выбор фото → сборка на сервере → правка страниц (сохраняется, книга в «Черновиках») → «Заказать» с проверкой (пустые рамки, разрешение, смаз) → оформление с доставкой и промокодом `PICPAC10` → лента статусов → «Есть проблема?» — обращение по заказу.

Если сервер недоступен, приложение работает на демо-данных; без Ollama дашборд остаётся в сценарном режиме.

Проверка: `cd services/api && docker exec api-db-1 createdb -U picpac picpac_test; uv run pytest` (84 теста), `cd services/assistant && uv run pytest` (27). Отчёт о тестировании — [notes/32-test-report.md](notes/32-test-report.md).

**Журнал действий и роли.** Каждое изменяющее действие (вход, загрузка фото, создание и сборка книги, правка страницы, заказ, обращение) пишется в `audit_log`: кто, роль, когда, что, над чем, код ответа и результат. Телефоны, тексты и тела запросов в журнал не попадают. Права проверяет сервер: роли `customer`, `manager`, `head`, `admin` в токене.

### Известные ограничения
- **Вход по SMS** работает только на стенде (`DEMO_MODE=true`, код `0000`); SMS-шлюза нет.
- **Оплата** не списывается: карта и ЕРИП — имитация; ЕРИП честно показывает «Ожидает оплаты». Эквайера нет.
- **Демо-данные в приложении** остаются для показа: прошлые заказы, сохранённые карты, идеи книг. Если сервер недоступен, приложение работает на демо, а сборка из своих фото показывает «Книга не собралась».
- **Черновики** — список на телефоне (сами книги на сервере); на новом телефоне после входа черновики не подтягиваются.
- **Удаление фото и аккаунта, ссылка общего альбома, голосовой ввод, ввод новой карты** спрятаны: на сервере их ещё нет.
- **«По описанию»** разбирает текст в приложении и собирает из демо-фото; серверный разбор с Ollama подключается отдельно.
- **Без Ollama** сервер разбирает описание и команды ИИ правилами, ассистент трека 3 не отвечает, дашборд — в сценарном режиме.
- **Дашборд Insight** читает демо-историю из своего файла; живые заказы и обращения видит ассистент через `/insight/data`.
- **Журнал действий** смотрится через API (`/docs`), отдельного экрана нет.
- **Пересборка при смене тарифа** не делается: стёрла бы ручные правки; при большем минимуме страниц приложение показывает, сколько будет пустых.
- Фото из iCloud, которых нет на телефоне, в книгу из альбома не попадают.

## Ценность

**Для клиентов picPac**
- Фотокнига без ручной раскладки: сейчас каждое фото вставляется в рамку вручную.
- Ни одного обрезанного лица: проверка кадра до оплаты, а не после печати.
- Понятная цена и срок сразу, статус заказа как у такси.
- Брак — по фото дефекта, без пересылки книги обратно.
- Ответы круглосуточно (сейчас поддержка с 9 до 21 и без телефона).

**Для «Фотопринта»**
- Короче путь до заказа — меньше брошенных корзин.
- Меньше брака и претензий за счёт проверки до печати.
- Руководитель видит причину отклонения сразу, а решения не теряются в почте и чатах.
- Единый справочник продуктов: на сайте сейчас 11 противоречий (сроки, допуски, единицы объёма, условия брака).
- Новые клиенты через общий альбом по QR-коду (выпускные, свадьбы) и реферальную программу.
- Данные и модели внутри контура компании.

Цифры эффекта на питче — только измеренные. Базовая линия текущего пути заказа: [#1](https://github.com/wolllipp/photoprintHac/issues/1).

## Стек

- **Приложение:** React Native (Expo). **Сайт и Insight:** Next.js. Общие токены дизайна.
- **Бэкенд:** Python + FastAPI, один сервис с модулями. **БД:** PostgreSQL + pgvector.
- **Модели:** локально через Ollama (LLM 7–8B), Whisper для встреч, лёгкие модели для лиц и качества фото.

Подробно: [notes/07-architecture.md](notes/07-architecture.md).
