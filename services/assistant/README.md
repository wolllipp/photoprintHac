# picPac Ассистент: агент руководителя

Реальный агент для экрана «Ассистент» в `design/insight`. Дизайн и обоснование: [notes/26-assistant-agent.md](../../notes/26-assistant-agent.md), идеи: [notes/27-assistant-ideas.md](../../notes/27-assistant-ideas.md).

## Запуск
```bash
brew install ollama && ollama serve &        # локальная модель
ollama pull qwen3:4b-instruct                 # проба на малой модели; на H200 — vLLM и модель крупнее
cd services/assistant && uv sync
uv run uvicorn app.server:app --port 8001
python3 -m http.server 8080 --directory ../../design/insight   # открыть http://localhost:8080 → «Ассистент»
uv run pytest                                 # 23 теста, модель не нужна
```
Другая модель или сервер: `ASSISTANT_MODEL`, `ASSISTANT_LLM_URL` (см. `.env.example`), любой OpenAI-совместимый API. Если сервис не запущен, макет остаётся в сценарном режиме со старыми заготовленными ответами.

## Устройство
| Файл | Что |
|---|---|
| `app/registry.py` | контракт инструмента `@tool(...)`, роли, риск `read/write/external`, маршрутизация 6–8 инструментов под вопрос |
| `app/agent.py` | цикл: вопрос → вызовы инструментов с проверкой прав → ответ со ссылками → проверка чисел |
| `app/policy.py` | маскирование ПДн, `<untrusted_data>`, подтверждения (`Pending`), журнал (`Audit`), поиск чисел без источника |
| `app/llm.py` | адаптер OpenAI-совместимой модели |
| `app/server.py` | `POST /chat` (SSE), `POST /actions/{id}/confirm|reject`, `/files/*`, `/audit`, `/meta` |
| `app/store.py` | данные: `data/demo.json` выгружен из `insight.js`, цифры совпадают с макетом |
| `app/tools/*.py` | плагины: **новый инструмент = новый файл или функция с `@tool`**, ядро не меняется |

## Инструменты (30, доступны и по MCP)
- **analysis:** `kpi_overview`, `explain_deviation`, `compare_periods`, `what_if`, `forecast_demand`, `spc_chart`, `check_effect`, `abc_xyz`, `unit_economics`, `run_python` (песочница)
- **artifacts:** `build_deck` и `build_docx` (содержимое проектирует сама модель, числа проверяются по данным диалога), `quarterly_deck` (готовый шаблон), `make_chart`, `pareto_defects`, `quarterly_deck` (pptx), `report_docx` (записка, ответ по претензии), `workbook_xlsx` (модель с формулами)

- **watch:** `morning_brief`, `threshold_watch`, `data_quality_check`, `customer_feedback`

## Самопроверка ответа
Ответ не вырезается и не правится кодом: если проверка нашла проблему (выдуманная ссылка, «выполнено» без вызова инструмента, число вне расчётов, просили файл, а он не создан), модель получает описание проблемы и переотвечает, до 2 раз. Что не удалось исправить, помечается «требует уточнения».

## Защита (проверено тестами)
- Роль `manager` не получает кадровые показатели; роли `admin` ассистент отказывает (403). Инструмента нет в списке роли, и вызов по имени отклоняется на сервере.
- Запись и отправка сообщений только карточкой подтверждения; подтвердить может тот, для кого подготовлено, один раз.
- Инструкция в запросе («игнорируй предыдущие…») блокируется до модели; тексты клиентов и записей идут модели как данные.
- Числа в ответе, которых нет в результатах инструментов, помечаются «требует уточнения».
- `run_python`: белый список импортов, без `open/exec/eval`, лимит CPU и времени, оператор скрыт от `manager`.

## Замер модели (12.11, MacBook, Ollama)
`uv run python tests/eval_model.py`: 10 русских вопросов, **10/10** по выбору нужного инструмента (8 задач и 2 отказа: зарплаты у менеджера и инъекция в запросе), утечек кадровых данных нет. Время ответа **3–9 с** на `qwen3:4b-instruct`.
Первая версия на `qwen3:4b` (с режимом размышлений) тоже набрала 10/10, но отвечала 12–170 с: модель писала рассуждения в ответ даже с `/no_think`. Поэтому по умолчанию вариант `-instruct` без размышлений. Тест также проверяет ответы автоматически: по-русски, не пустой, числа есть в расчётах, нет вывода «из-за поставщика» без доказательств. Два прогона: 10/10 по всем проверкам и 9/10 по «числа обоснованы» (проверка пометила одно число; модель недетерминирована). Смысловое качество формулировок автоматически не оценивается, это ручная проверка на вопросах руководителя. Первый запрос после простоя дольше из-за загрузки модели: `OLLAMA_KEEP_ALIVE=1h`.

## Проверка интерфейса
Макет прогнан в настоящем Chromium (Playwright) против живого сервиса: график загружается (933×487), pptx скачивается (133 КБ), карточка подтверждения работает, ошибок страницы нет. Найдены и исправлены нечитаемая плашка файла и ложное «ждёт подтверждения» в ответе на чтение.

## MCP-сервер (`app/mcp_server.py`)
Те же 27 инструментов доступны любому MCP-клиенту (Claude, CRM, другой агент):
```bash
ASSISTANT_MCP_ROLE=ceo uv run python -m app.mcp_server     # stdio; роль фиксируется при запуске
```
Права по роли и журнал те же. Запись и отправка сообщений через MCP не выполняются: инструмент возвращает `pending_action_id`, подтвердить может только человек в CRM (`POST /actions/{id}/confirm`). Тексты клиентов и коллег помечены недоверенными. Проверено настоящим MCP-клиентом по stdio: список инструментов, `what_if`, `propose_task`.
В обратную сторону: если у CRM заказчика есть MCP-сервер или REST API, адаптер данных в `connectors.py` подключается к нему.

## Коннекторы (`app/connectors.py`)
Инструменты работают с интерфейсами, подключение реальных систем = адаптер и переменная окружения:
- Telegram: `ASSISTANT_MESSENGER=telegram`, `ASSISTANT_TG_TOKEN`, `ASSISTANT_TG_CHATS` (роль → chat_id); отправка и чтение ответов (инструмент `check_replies`), проверено на подмене Bot API, с реальным ботом не запускалось.
- Мессенджер: `ASSISTANT_MESSENGER=webhook` и `ASSISTANT_MESSENGER_URL` (POST `{to,text,from}`, ответ `{"reply": "..."}` или `{}` если ответ придёт позже). По умолчанию демо-адаптер с заготовленными ответами.
- Данные: `ASSISTANT_DATA_URL` с JSON в формате `data/demo.json` (выгрузка витрин CRM). По умолчанию демо-данные.
Реальной CRM у проекта нет: CRM — это макет `design/insight`. Если системы «Фотопринта» появятся, достаточно написать адаптер.

## Ограничения демо
- Мессенджер и источник данных по умолчанию демо; реальные подключаются через `app/connectors.py`, но под системы заказчика не написаны.
- Роль берётся из заголовка `X-Role`; в продукте — JWT CRM.
- Песочница `run_python` изолирует процесс и код, но не сеть на уровне ОС. В продукте — контейнер без сети.
- Модель 4B может неточно формулировать выводы: числа защищены проверкой, но качество текста и цепочек из нескольких инструментов не измерено.
