# Руководство: презентация как HTML-страница (make_slides)

Ты верстаешь слайды как веб-страницу, а браузер расставляет всё сам: центровку, отступы, перенос строк, сетку. Координат в дюймах нет. Получается редактируемый pptx, pdf и картинки слайдов. Шаблонов нет: посыл, структуру и дизайн придумываешь ты под тему и аудиторию.

## Каркас
```html
<!doctype html><meta charset="utf-8"><style>
*{box-sizing:border-box;margin:0}
body{font-family:Helvetica,Arial,sans-serif}
.slide{width:1280px;height:720px;position:relative;overflow:hidden;padding:64px;display:flex;flex-direction:column}
/* палитру и шрифты задай переменными и применяй везде */
</style>
<section class="slide">…</section>
<section class="slide">…</section>
```
Каждый слайд ровно 1280×720, блок `<section class="slide">`. Скрипты, внешние ссылки, @import запрещены. Шрифты только системные (Helvetica, Arial, Georgia, Verdana).

## Как делать хорошо
1. Реши посыл: что аудитория поймёт и сделает после. Слайды строятся вокруг него, а не вокруг оглавления.
2. Заголовок слайда — вывод («Брак вырос втрое за две недели»), а не тема («Брак»).
3. Палитра под тему: вулканы — тёмные земляные и огненные, финансы — сдержанные, детям — яркие. 1 фон, 1 акцент, 1–2 нейтральных. Контраст текста с фоном высокий.
4. Чередуй раскладки: титул на весь экран, крупное число с подписью, две колонки, карточки в сетке (grid), диаграмма и вывод, схема из блоков со стрелками, таймлайн, цитата, итог с действиями. Одинаковые слайды подряд — провал.
5. Одна мысль на слайд, текст ≥ 18px (лучше 22+), заголовок 40–64px. Не больше 40 слов.
6. Центровку делай flex/grid: `display:flex;align-items:center;justify-content:center`. Не двигай элементы `position:absolute` без нужды.
7. Числа показывай диаграммой, а не списком. Диаграммы рисуй SVG (ниже), у каждой подпись-вывод.
8. Числа по компании считай кодом (run_python) и бери из результатов инструментов, из головы не вставляй. Источник пиши словами («данные производства за недели 40–45»).

## Диаграмма SVG (столбцы с подписями)
```html
<svg viewBox="0 0 520 300" width="520" height="300">
  <g font-family="Helvetica" font-size="16" fill="#f5efea">
    <rect x="40"  y="60"  width="90" height="200" rx="8" fill="#ff6b35"/><text x="85"  y="285" text-anchor="middle">Ricoh</text><text x="85" y="50" text-anchor="middle">3,1%</text>
    <rect x="170" y="170" width="90" height="90"  rx="8" fill="#6b5b55"/><text x="215" y="285" text-anchor="middle">Fuji</text><text x="215" y="160" text-anchor="middle">1,4%</text>
  </g>
</svg>
```
Высоты считай кодом: `высота = значение / максимум * 200`. Линейный график: `<polyline points="…" fill="none" stroke="#ff6b35" stroke-width="4"/>`. Круг: `<circle>` со `stroke-dasharray`. Графики из расчётов можно сохранить в png через run_python (matplotlib) и вставить `<img src="chart.png" style="width:560px">` (файл лежит в рабочей папке).

## Что конвертер pptx переносит хорошо
Flexbox и grid, скругления, градиенты, тени, SVG, картинки из рабочей папки, обычный текст в `<h1>…<p>…<li>…<span>`. Избегай: фильтры (blur), `background-clip:text`, `mix-blend-mode`, сложный `clip-path`, анимации.

## Замечания
После вызова вернётся список проблем вёрстки (текст не помещается, наложение, выход за край, мелкий шрифт). Они точные, браузер считает их по реальной раскладке. Исправь HTML и вызови make_slides снова с тем же именем: файлы заменятся. Чтобы доработать готовую колоду, прочитай `имя.html` через read_file и передай исправленный HTML целиком.

## Показ файла пользователю
Собранная презентация лежит в рабочей папке, но пользователь её не видит. Когда файл окончательный (замечания по вёрстке исправлены), вызови show_files с именами нужных файлов (обычно pptx и pdf) и только после этого пиши «Готово».
