# Архитектура и стек picPac One

Задача: [#26](https://github.com/wolllipp/photoprintHac/issues/26). Статус: **принята как рабочая 09.11** (можно править по ходу), ждём подтверждения Марка и Сени по открытым пунктам.
Пометки: **Решено** — уже согласовано командой; **Рекомендация** — предложение, ждёт подтверждения; **Открыто** — нужна информация.

## 1. Общая схема

```
 [Приложение picPac]        [Сайт picPac]        [picPac Insight + Ассистент]
   React Native (Expo)        Next.js               Next.js (тот же проект, раздел /insight)
          \                      |                      /
           \_____________ HTTP / JSON API _____________/
                                 |
                       [API-сервис: FastAPI]
            auth и роли · заказы · события · витрины · журнал
                 |                         |
        [PostgreSQL + pgvector]     [AI-модули (внутри API или отдельный процесс)]
         данные, события,            автосборка, качество фото, Story Mode,
         витрины, эмбеддинги,        ассистент, распознавание речи
         журнал                              |
                                     [Ollama: локальная LLM]
```
Всё работает на одной машине в локальной сети. Внешних API нет.

## 2. Клиенты
- **Решено:** мобильное приложение на React Native (Expo), сайт отдельно на React. Общие токены дизайна в `packages/theme`.
- **Рекомендация:** сайт, дашборд Insight и чат ассистента — **один проект Next.js** с разными разделами (`/` для клиентов, `/insight` для руководителя). Один фронтенд-проект вместо двух экономит время Ване и Илье, при этом для жюри это разные продукты.
- **Рекомендация:** графики дашборда — Recharts или ECharts (выбрать на ревью R1).

## 3. Бэкенд
- **Рекомендация:** **Python + FastAPI**, один сервис (модульный монолит): модули `api`, `data` (пайплайн, витрины, отклонения), `ai` (модели), `security` (роли, маскирование, журнал).
  - Почему Python: AI-часть Марка всё равно на Python, один язык упрощает интеграцию и деплой на одну машину.
  - Почему монолит: на хакатоне микросервисы — лишняя работа; границы модулей сохраняем, чтобы на слайде показать путь к разделению.
- **Открыто:** на чём привык писать Сеня. Если Node.js — альтернатива: API на NestJS + отдельный Python AI-сервис. Это дороже по времени.
- **Рекомендация:** Python 3.11+ через `uv` (системный Python 3.9 на ноутбуке Вани устарел).

## 4. База данных
- **Рекомендация (из notes/03):** один PostgreSQL на всё: операционные данные, события, витрины (SQL-представления), эмбеддинги (pgvector), журнал.
- PostgreSQL 14 у Вани уже стоит, pgvector поддерживает 14. Docker не установлен, ставим через Homebrew.
- Ассистент ходит в БД под **отдельной ролью только на чтение** и только к разрешённым витринам.

## 5. Локальные модели
Ограничение: MacBook Air M3, 16 ГБ общей памяти (на ней же работают БД, Expo, браузер), **14 ГБ свободного диска**. Конкретные модели выбираем тестом на наших русских запросах; названия ниже — кандидаты, версии проверить перед загрузкой.

| Задача | Рекомендация | Размер (порядок) |
|---|---|---|
| LLM ассистента и разбор запросов Story Mode | модель 7–8B в 4-битной квантизации через **Ollama**; кандидаты с хорошим русским: семейство Qwen, T-lite, Llama. Сравнить 2–3 на 10 наших вопросах | ~5 ГБ |
| Эмбеддинги текста (поиск по документам, M4) | мультиязычная модель (например bge-m3 или multilingual-e5) | 0,5–2 ГБ |
| Поиск фото по тексту (Story Mode) | мультиязычная текстово-картиночная модель (семейство CLIP/SigLIP с поддержкой русского) или перевод запроса на английский локальной LLM + обычный CLIP | ~1 ГБ |
| Лица и главный объект (A8) | лёгкий детектор лиц (MediaPipe или OpenCV YuNet) + карта значимости | < 50 МБ |
| Резкость, дубли, разрешение (A8) | без нейросетей: дисперсия Лапласиана, перцептивный хэш, проверка пикселей | — |
| Распознавание речи (M3) | Whisper через **whisper.cpp (Metal) или mlx-whisper** — используют GPU M3; faster-whisper на Mac только CPU. Модель large-v3-turbo, если устроит скорость, иначе small. Режим: загрузка готовой записи, без живой транскрибации. Разделение по говорящим — не делаем, на слайд | 0,5–1,6 ГБ |

- **Правило:** числа считает код, LLM только формулирует вывод (из notes/03).
- **Риск:** MacBook Air без вентилятора, при долгой нагрузке LLM замедляется. Целевое время: ответ ассистента до ~10 с, автосборка книги из 40 фото до ~30 с (проверить замером, потом зафиксировать).
- **Риск:** диска не хватит. Модели + node_modules (Expo, Next.js) + БД ≈ 10–12 ГБ. Освободить хотя бы до 30 ГБ свободного места до 11.11.

## 6. Безопасность (M5, D11, A14)
- **Аутентификация:** JWT, роли клиент / менеджер / руководитель / администратор.
- **Права проверяются в API до вызова инструмента**, а не в промпте модели.
- **Маскирование ПДн** перед отправкой текста в LLM и в журнал: телефоны, почты, ФИО (правила + словарь имён из данных).
- **Недоверенные тексты** (документы, запросы Story Mode, комментарии, чат «Обсудить») передаются модели как данные в отдельном блоке; инструменты по белому списку; запись (задачи, решения) только через подтверждение человеком.
- **Журнал:** таблица `audit_log` (кто, когда, вопрос, какие витрины и документы, ответ).
- **Фото клиентов:** хранятся локально, удаляются по сроку и по запросу (A14).

### Один ассистент, разные роли (решение 09.11)
Ассистент есть и в клиентском приложении: это тот же движок picPac Ассистента, разделённый по ролям.

| | Клиент (приложение, сайт) | Сотрудники (Insight) |
|---|---|---|
| Функции | Story Mode, вопросы о сроках, доставке и форматах, статус своего заказа, претензия по браку | Анализ причин, встречи, протоколы, документы, задачи |
| Инструменты | только клиентские; инструменты сотрудников **не регистрируются** для этой роли | по роли пользователя |
| Данные | только свои заказы, проекты, фото (построчная защита в БД, отдельная роль БД) | витрины по правам роли |
| Документы | **отдельный публичный индекс**: справочник D14, FAQ, условия | внутренние документы по правам |

- Изоляция обеспечивается в API и БД, а не текстом промпта.
- Отдельные системные промпты и лимиты запросов для клиентской роли.
- Вопросы и жалобы клиентов (с маскированием ПДн) идут в данные Insight как сигнал.
- **Демо-момент:** клиент просит «покажи выручку компании» или вставляет инструкцию — ассистент отказывает, потому что у роли нет такого инструмента.

## 7. Демо и сеть
- **Демо-машина:** одна, на ней БД, API, модели и веб. **Открыто:** какой ноутбук самый мощный в команде.
- **Телефон ↔ ноутбук:** Expo Go подключается по локальной сети. **Риск:** Wi-Fi площадки может изолировать устройства. Решение: раздавать сеть с телефона или ноутбука, проверить на месте в первый же час.
- **Офлайн-демо:** показать, что интернет выключен, а всё работает (модели заранее скачаны).
- **Запасной вариант:** режим `DEMO_MODE` с заранее посчитанными результатами для каждого шага сценария, если модель тормозит.
