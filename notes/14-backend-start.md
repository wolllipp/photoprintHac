# Бэкенд: с чего начать (для Сени)

Ответственный: Сеня. Основа: [07-architecture.md](07-architecture.md), [03-data-design.md](03-data-design.md), [04-use-cases.md](04-use-cases.md). Экраны, которые обслуживает бэкенд: `design/app/journey.html`.

**Цель к демо (12.11, 17:45):** один сервис, который проводит сквозной сценарий: черновик/описание → книга → заказ → этапы производства → данные в Insight → отклонение → решение. Всё остальное — потом.

## 1. Стек и каркас
- Python 3.11+ через `uv`, **FastAPI**, Pydantic v2, SQLAlchemy 2 + Alembic, `asyncpg`.
- **PostgreSQL** (у Вани стоит 14) + **pgvector**. Docker не обязателен: `brew install pgvector`.
- Монорепо, папка `services/api`:

```
services/api/
  app/
    main.py            # FastAPI, роутеры
    config.py          # настройки из .env
    db.py              # движок, сессии
    models/            # SQLAlchemy-модели
    api/               # роутеры: auth, catalog, projects, orders, events, points, insight, assistant
    data/              # витрины, отклонения, проверка эффекта (D2–D8)
    ai/                # интерфейс к модулям Марка (заглушки → реальные)
    security/          # роли, маскирование ПДн, журнал
    jobs.py            # фоновые задачи (сборка книги)
  migrations/          # Alembic
  tests/
  pyproject.toml
  .env.example
```

- **Первый шаг:** `GET /health`, подключение к БД, первая миграция, `README` с запуском одной командой.
- **Можно ли приносить заготовки на хакатон — ещё не подтверждено.** Каркас и схему готовим, но будем готовы показать, что код написан на месте (история коммитов).

## 2. Модель данных (ядро)
Деньги — `numeric(10,2)` в рублях. Время — `timestamptz`. Справочные значения — enum или отдельные таблицы.

**Справочник и каталог (D14 — один источник правды, без 11 противоречий сайта)**
- `products` — линейка: Lite, Classic, Premium, фотопечать цифровая/фотохимическая.
- `product_options` — формат, обложка, ламинация, мин/макс страниц и фото, цена за базу и за доп. разворот, срок изготовления, линия печати.
- `delivery_methods` — Европочта ПВЗ/курьер, Белпочта, EMS: цена, порог бесплатной доставки, срок.

**Клиент и проекты**
- `users` — телефон, имя, роль (`customer`, `manager`, `head`, `admin`), созданный по OTP.
- `pickup_points` — сохранённый пункт выдачи пользователя («мой пункт»).
- `photos` — владелец, путь к файлу, дата съёмки, размеры, метрики качества (резкость, разрешение), лица (bbox jsonb), `embedding vector`, флаг «отобрано», срок удаления (A14).
- `projects` — книга: владелец, продукт и опции, **тема** (из Story Mode — нужна и для иконки на главной), статус (`draft`, `building`, `ready`, `ordered`), источник (`gallery_draft`, `story`, `manual`), число страниц.
- `project_pages` — развороты: раскладка jsonb (какое фото в какой рамке, кадрирование).
- `build_jobs` — задача автосборки: статус и этапы (`selecting`, `layout`, `faces`, `captions`), прогресс — для экрана «Собираем книгу».

**Заказы и производство**
- `orders` — клиент, итог, доставка, адрес/ПВЗ, оплата (`card`, `erip`), списано пиков, статус.
- `order_items` — проект или фотопечать, цена, кол-во.
- `order_stages` — **история этапов**: `accepted`, `layout_checked`, `printing`, `binding`, `handed_to_delivery`, `ready_for_pickup`, `delivered`; время, линия, смена. Отсюда экран отслеживания и Live Activity.
- `production_progress` — «готово 6 из 12 разворотов» по заказу (обновляет генератор/производство).
- `production_lines` (Fuji Frontier, Ricoh, Noritsu), `shifts`, `employees`.
- `claims` — претензия по браку: заказ, фото дефекта, тип, решение (`reprint`, `return`, `rejected`) — экран 9 и A13.

**Пики и рефералка (G3)**
- `points_ledger` — движения пиков: +/−, причина (`referral`, `story_conversion`, `moment`, `order_payment`), ссылка на заказ. Баланс = сумма. Цена пика и правила — Алеся (#30).
- `referral_links` — код, владелец, источник (`story`, `share`, `qr_album`), переходы, заказы.

**События клиентского пути (A6)**
- `events` — пользователь/сессия, имя события, `props jsonb`, время. Схему событий согласовать с Алесей.

**Insight (трек 1)**
- Витрины — SQL-представления поверх таблиц выше: выручка, маржа, брак по линиям и сменам, воронка, сроки.
- `deviations` — отклонение: метрика, разрез, значение, норма, статус.
- `decisions` — решение: причина, действие, ответственный, срок, статус, ожидаемый эффект; `effect_checks` — проверка эффекта (D8).
- `meetings`, `tasks` — для ассистента (M2, M3).

**Ассистент и безопасность**
- `documents`, `document_chunks` (`embedding vector`) — для поиска; отдельный **публичный индекс** для клиента.
- `audit_log` — кто, что спросил, какие витрины и документы, ответ.

**Моменты (P1, после демо)** — `albums` (пресет, тема, обложка), `moments` (фото, дата, подпись), `stories`.

## 3. API под экраны
| Экран | Методы |
|---|---|
| Вход (оформление) | `POST /auth/otp/request`, `POST /auth/otp/verify` (в демо код фиксированный) |
| Главная | `GET /me` (баланс пиков), `GET /home` (черновики «Собрали для вас», мои альбомы, текущий заказ) |
| Опишите книгу | `POST /projects/story` → `{parsed, project_id}` (разбор — Марк) |
| Собираем книгу | `POST /projects/{id}/build` → `job_id`; `GET /jobs/{id}` (этапы и прогресс) |
| Отбор фото | `GET /projects/{id}/selection`, `PATCH /projects/{id}/selection` (вернуть фото) |
| Книга и цена | `GET /projects/{id}`, `GET /catalog/quote?project_id&product&options` (цены и даты для всех тарифов) |
| Оформление | `POST /orders` (доставка, ПВЗ, оплата, списание пиков) → итог |
| Отслеживание | `GET /orders/{id}` (этапы, прогресс, дата); позже — веб-сокет или опрос раз в 10 с |
| Брак | `POST /claims` (фото дефекта) → решение |
| События | `POST /events` (пакетом) |
| Insight | `GET /insight/kpi`, `GET /insight/drilldown?metric&dims`, `GET/POST /deviations`, `POST /decisions` |
| Ассистент | инструменты только на чтение по витринам; запись (задачи, решения) — через подтверждение пользователем |

## 4. Стыки с командой
- **Марк (AI):** Сеня даёт хранение фото и проектов, очередь `build_jobs` и интерфейс в `app/ai/`. Начать с **заглушек** (фиксированный результат для «Карелии»), Марк потом подменяет реальными функциями: `parse_story(text)`, `select_photos(photo_ids)`, `layout(project)`, `check_quality(project)`, `assistant_answer(question, user)`. Заглушки = запасной `DEMO_MODE`.
- **Алеся:** генератор тестовых данных (D0) пишет в эти таблицы; витрины и правила отклонений — её формулы, Сеня делает SQL. Схема событий A6 — вместе.
- **Ваня и Илья (фронт):** контракты ответов API — по экранам из `journey.html`; поля и названия согласуем до вёрстки.

## 5. Безопасность (минимум к демо)
- JWT, роли; права проверяются **в API до вызова инструмента**, а не в промпте.
- Клиент видит только свои данные: фильтр по владельцу в каждом запросе (позже — построчная защита в PostgreSQL).
- Ассистент ходит в БД отдельной ролью **только на чтение** и только к витринам.
- Маскирование телефонов, почт, ФИО перед текстом в LLM и в журнал.
- Фото удаляются по сроку (A14).

## 6. Порядок работы
1. Каркас, БД, миграции, `/health`, сид справочника (цены и сроки с сайта, без противоречий).
2. Пользователи и OTP-заглушка, проекты, фото, `build_jobs` с заглушками ИИ.
3. Каталог и расчёт цены, заказы, этапы, прогресс — **путь до оформленного заказа работает**.
4. События и загрузка данных генератора Алеси, витрины, отклонения, решения, проверка эффекта.
5. Роли, журнал, инструменты ассистента только на чтение.
6. Пики и реферальные ссылки (если успеваем).

**Готово к демо, когда:** по API можно пройти путь А (черновик → заказ), заказ проходит этапы, данные видны в витринах, одно отклонение доходит до решения.
