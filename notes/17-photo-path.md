# Путь фотографии: где фото в каждый момент

Записано 11.11. Пометки как в notes/07: **Решено**, **Рекомендация**, **Открыто**.

**Открыто: какой вход основной.** Ваня с Алесей обсуждали два варианта:
- **А. Только выбранные фото** (предложение Алеси, notes/08). Человек сам выбирает фото или альбом, AI работает только с ними. Так сейчас устроен бэкенд.
- **Б. Подборки из всей галереи.** Человек даёт доступ ко всей галерее, телефон сам собирает подборки по датам и поездкам. Ничего не отправляется, пока человек не выберет подборку для книги.

**Позиция Вани (11.11):** первоначальная идея (Б) хорошая, хочется её оставить.

**Рекомендация: Б в облегчённом виде, А — запасной путь.**
- **Дал доступ ко всей галерее** → телефон собирает подборки **только по датам и местам** из данных снимков, не открывая сами картинки. Человек выбирает подборку → её фото уходят на сервер, и дальше всё как сейчас: отбор лучших, дубли, лица, сборка.
- **Дал доступ к части фото или не дал совсем** → обычный выбор фото (А). Подборки не показываем.

Почему так, а не полный Б:
1. **Время.** Обработка картинок на телефоне (дубли, резкость, «что в кадре») — это тяжёлая часть Б. Её не делаем: качество уже проверяет сервер Марка, только для выбранной подборки. На телефоне остаётся `expo-media-library` и группировка по датам на JavaScript.
2. **Частичный доступ** (довод Алеси) закрывается запасным путём А.
3. **Лица и закон № 99-З.** Лица анализируются только на сервере и только у выбранных фото, как и в варианте А. Риск тот же.
4. **Обещание для питча остаётся честным:** «Подборки по датам собирает ваш телефон. К нам попадает только подборка, которую вы выбрали».

Что ещё не решено: может ли Б-лайт работать в Expo Go на SDK 58, или нужна пересборка приложения. Проверить в документации `expo-media-library`.

Шаги со второго этапа одинаковы для обоих вариантов, поэтому их можно делать уже сейчас.

## 1. Как фото попадает в работу

### Вариант А: человек выбирает фото сам (основной)

| # | Момент | Где фото | Что знает сервер | Сейчас в коде |
|---|---|---|---|---|
| А0 | Установил приложение | Только в галерее телефона | Ничего | — |
| А1 | Выбрал фото или альбом для книги | Системное окно выбора фото: приложение получает доступ только к ним, остальная галерея закрыта | Ничего | В приложении нет: экраны работают на демо-фото, `expo-image-picker` установлен, но не используется |
| А2 | Подтвердил выбор | **Первый раз уходят на сервер:** оригиналы выбранных фото, по HTTPS, на сервер picPac в локальном контуре | Выбранные фото | Есть: `POST /photos` сохраняет фото в `storage/<id пользователя>/` |

В варианте А фото уходят на сервер уже при выборе, а не при оплате: отбирает и собирает книгу сервер.

### Вариант Б: подборки из галереи (функция «Моменты», выключена по умолчанию)

| # | Момент | Где фото | Что знает сервер | Сейчас в коде |
|---|---|---|---|---|
| Б0 | Включил «Моменты» и дал доступ ко всей галерее | В галерее. Приложение читает только список: дата, координаты, размер, «скриншот или нет». Индекс хранится на телефоне | Событие «доступ дан» | Нет |
| Б1 | Появились подборки | В галерее. Подборка — список ссылок на фото, не копии | «подборок: N» | Нет |
| Б2 | Лучшие кадры в подборке | Телефон делает уменьшенные копии (64–256 px) во временной папке, считает дубли, резкость, метки «что в кадре» и удаляет копии | Ничего | Нет |
| Б3 | Голосовой запрос | Фото не двигаются. Наверх уходит текст (или аудио, если не справилось встроенное распознавание), обратно — фильтры | Текст запроса | Разбор текста есть (`parse_story`), фильтров для поиска нет |
| Б4 | Нажал «Собрать книгу» из подборки | **Первый раз уходят на сервер:** оригиналы фото этой подборки | Выбранные фото | Дальше как в А2 |

## 2. Общий путь после загрузки (одинаков для А и Б)

| # | Момент | Где фото | Сейчас в коде |
|---|---|---|---|
| 1 | Проверка при загрузке | На сервере: формат, размер до 40 МБ, дата съёмки, резкость, лица | Есть: `photos.py`, `ai/quality.py` |
| 2 | Отбор и сборка макета | На сервере: дубли, смазанные, разрешение под формат, лица у края, раскладка по разворотам | Есть: `jobs.py` (`run_build`), `ai.select_photos`, `ai.layout` |
| 3 | Доступ к фото | Только владелец: чужие фото не видны и не прикрепляются к проекту | Есть: `photo_file`, `attach` |
| 4 | Оплата и производство | Файлы макета уходят на печатные машины «Фотопринта» | Нет: передачи в производство пока нет |
| 5 | Доставка и брак | Фото нужны на сервере для перепечатки по претензии (A13) и для повторного заказа | Нет |
| 6 | **После заказа** | **Открыто:** сколько хранить и как удалять | Нет: удаления фото нет вообще |

## 3. Куда фото не попадают никогда

- **picPac Insight** — руководитель видит только события и цифры.
- **Ассистент руководителя** — работает с данными компании, к фото клиентов доступа нет. Проверять по ролям в API (notes/07, раздел 6).
- **Внешние сервисы** — ни облачного AI, ни геокодирования Apple и Google. Название места переводим в область на нашем сервере, и телефон сравнивает её со своими координатами.

## 5. Открытые вопросы

1. **Основной вход.** Рекомендация: Б-лайт с запасным путём А (см. выше). Подтвердить Ване и обсудить с Алесей.
2. **Срок хранения фото после доставки.** Нужен для претензий по браку: пики активируются через 14 дней после доставки (notes/16), фото стоит хранить не меньше. Дальше удалять или хранить для повторного заказа с согласия?
3. **Оригиналы или сжатые копии при загрузке.** Для печати нужно 300 DPI, значит скорее оригиналы. Это 3–10 МБ на фото по мобильной сети.
4. **Голосовой запрос в варианте А** ищет только по загруженным фото. Хватит ли этого, или голос нужен именно для поиска по галерее?
