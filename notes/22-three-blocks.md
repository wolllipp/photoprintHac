# Три блока: пользователь, руководитель, ядро

Записано 11.11 на площадке. Продолжение notes/19 (движок), notes/20 (описание решения), notes/21 (ассистент). Раздел 1 — слова организаторов и видение Вани. Всё остальное — **рекомендация**, с командой не согласовано.

## 1. Что сказали организаторы и директора

- Приложение для пользователей они видят **в виде соцсети**.
- Для руководителей — **дашборды с аналитикой**.
- ИИ — **помощник**: анализирует, смотрит, назначает встречи.

**Видение Вани — три блока:**

| Блок | Что это |
|---|---|
| **Пользователь** | Приложение в виде соцсети со встроенным ИИ: лента, обмен альбомами, пики, вдохновение |
| **Руководитель** | Рабочее место со встроенным ИИ: анализ, риски, предположения. Десктоп и телефон. На телефоне — в стиле Qalta: микрофон, вопросы голосом, решения в разговоре |
| **Ядро** | Одна модель связывает пользователей и руководителей, анализирует и помогает |

Ядро совпадает с «один движок, разные роли» из notes/19. Новое: соцсеть у клиента, голосовой режим руководителя на телефоне, назначение встреч.

## 2. Что берём из Mera

Источники: приложение `~/Developer/crypto-analytics-app` (`src/chat.tsx`, `src/model.ts`), сервер ассистента `research/src/crypto_analytics/api/assistant.py` в папке проекта Mera.

| Практика в Mera | Как перенести в picPac |
|---|---|
| **Риск — диапазон сценариев, а не прогноз.** «8 из 10 сценариев», «сильное падение — 1 неделя из 10», считается по прошлым неделям | «Брак на линии 2: в 8 неделях из 10 будет 14–22 претензии, в плохую неделю до 30». Считается пересборкой прошлых недель из наших данных |
| **Лимит задаёт человек.** «Сколько готов потерять» → сумма в пределах лимита | Руководитель задаёт допуск: брак не выше 3 %, срок не дольше 5 дней. Риск — когда плохой сценарий выходит за допуск |
| **Цифры собирает сервер, модель только пересказывает** (`market_note`, `plan_note`, `journal_note`) | Уже заложено: каталог метрик и проверка чисел (notes/19, раздел 2) |
| **Журнал решений с исходом через неделю** | Наша проверка эффекта: решение → сравнение «до» и «после» |
| **Один жёсткий запрет + проверка каждого ответа (`flags`) + набор провокаций перед выпуском** с кодом ошибки | Запрет: ассистент не называет виновного сотрудника и не выдаёт предположение за факт. Набор атак — тест, результат числом на слайде |
| **Голос распознаёт телефон** (звук не уходит с устройства), **карточка «Поняли так» строится без модели**, действие — по кнопке | Основа мобильного режима руководителя. `voiceGlow.tsx` в приложении уже есть |
| **Ассистента не видно, если сервер недоступен**; лимит запросов на пользователя | Берём как есть |

**Не берём:** внешнюю модель. В Mera ответы идут через OpenRouter, у нас вся защита стоит на локальной модели.

Числа в примерах (14–22, 3 %, 5 дней) — иллюстрация, не данные.

## 3. Блок «Руководитель»

**Три типа ответа, помеченные на экране.** Закрывает «анализировать, выявлять риски, строить предположения»:

| Тип | Что это | Откуда |
|---|---|---|
| **Факт** | Цифра со ссылкой на источник | Витрина, каталог метрик |
| **Риск** | Диапазон сценариев против допуска | Пересборка прошлых недель, считает код |
| **Предположение** | Гипотеза о причине: на чём основана и как проверить | Раскладка по разрезам + текст модели |

- **Десктоп:** дашборды и путь от цифры к причине. Три экрана из notes/19: показатели с отклонением, карточка отклонения, чат.
- **Телефон:** не уменьшенный дашборд, а один экран в стиле Qalta. Главное отклонение дня крупно, микрофон по центру, ответ карточкой с кнопками «Назначить встречу» и «Создать задачу».
- **Встречи:** ассистент предлагает повестку, участников и время. Человек подтверждает, запись идёт в нашу таблицу `meetings`. Внешний календарь не подключаем: система работает без интернета.
- **Мобильный режим — в том же приложении, по роли.** Экран ассистента и голос там уже есть.
- **Слово «CRM»** не используем, если директора сами его не называли: CRM — это база клиентов и сделок, а здесь рабочее место руководителя.

## 4. Блок «Пользователь»: соцсеть

**Главный риск:** соцсеть спорит с обещанием «фото видит только владелец» (notes/17, notes/20).

Как совместить:
- **В ленту попадает только то, что человек сам опубликовал.** Отдельное действие с согласием, по умолчанию всё закрыто.
- **Лента ведёт к заказу.** Кнопка «Собрать такую же из моих фото» — здесь работает ИИ.
- **Пики** начисляются за заказ по твоему альбому — стыкуется с рефералкой из notes/16.
- **Связь с ядром:** что сохраняют и повторяют в ленте, руководитель видит как спрос.

## 5. Что успеем к отбору

В коде нет Insight, ассистента и веб-части, приложение не связано с сервером (notes/19, раздел 6).

1. Сквозной срез из notes/19, раздел 7, остаётся основой.
2. Лента — один экран на демо-данных и настоящее «поделиться альбомом» (экраны `shared/` уже есть).
3. Голосовой экран руководителя — один вопрос и одна карточка с подтверждением встречи.

**Проверить в первый час:** системное распознавание речи не работает в Expo Go, нужна пересборка приложения.
