## 3. Проблемы

Серьёзность: **К** — критично, **В** — высоко, **С** — средне, **Н** — низко.

### Критично

**К-1. В продукте вход по телефону всегда принимает код «0000», SMS не отправляется.**
`app/api/auth.py:59` сравнивает код с `settings.otp_demo_code` **независимо от `DEMO_MODE`**; `otp_request` (`auth.py:50-52`) ничего не отправляет и не хранит.
Воспроизвести: `POST /auth/otp/verify {"phone":"<любой номер>","code":"0000"}` → токен владельца номера. Гость, вошедший так, получает аккаунт жертвы, а его черновики вливаются к ней (`auth.py:66-74`, проверено: у жертвы появился проект «СПАМ от гостя»).
Сделать: таблица `otp_codes` (телефон, хэш кода, срок 5 мин, счётчик попыток ≤ 5). Код «0000» — только при `DEMO_MODE=true`, и при старте падать, если `DEMO_MODE` включён вне dev-окружения. Ограничить частоту `otp/request` и `otp/verify` по номеру и IP.

**К-2. Мобильный клиент входит всех людей под одним номером.**
`apps/mobile/src/api/client.ts:88` — `ensureRegistered(phone = '+375291234567')`, `client.ts:92` — `code: '0000'`; вызывается из `book.ts:155, 190` без номера.
Воспроизвести: два устройства оформляют заказ → оба получают один аккаунт; второе видит фото, проекты и заказы первого и двигает их стадии (проверено: `GET /orders`, `GET /photos/{id}/file`, `/dev/orders/{id}/advance` → 200).
Сделать (это фронтенд, но ломает всю модель доступа бэкенда): передавать номер из `checkout.tsx` (`phone` в store уже есть) и код, который вводит человек. Бэкенд по К-1 перестанет принимать 0000.

**К-3. Секрет JWT по умолчанию зашит в код, конфигурация по умолчанию — демо.**
`app/config.py:8` (`jwt_secret = "dev-secret-change-me-in-production-0123456789"`, то же в `.env.example:2`), `config.py:9` (`demo_mode = True`), `config.py:10`. Файла `.env` в `services/api` нет: сервер, запущенный по README без правки `.env`, подписывает токены публичным секретом.
Воспроизвести: `jwt.encode({"sub": "<user_id>", "exp": …}, "<секрет из config.py>", "HS256")` → `GET /orders` 200. Id пользователя отдаётся в `/me` и `/auth/*`.
Сделать: без значения по умолчанию (`jwt_secret: str`, обязательный, длина ≥ 32), `demo_mode: bool = False`. При старте отказываться работать с секретом из `.env.example`.

**К-4. Демо-ручки включены по умолчанию: бесплатные пики и ручная смена стадии заказа.**
`app/main.py:11` подключает `app/api/dev.py`, если `demo_mode` (по умолчанию True). `dev.py:41-45` — `POST /dev/points?amount=` начисляет любое число пиков (в том числе отрицательное; 1e12 → 500), `dev.py:16` двигает стадию своего заказа. Клиент сам вызывает `/dev/points` перед каждым заказом (`book.ts:157, 192`).
Сделать: `demo_mode=False` по умолчанию; `amount` ограничить `Query(ge=1, le=10000)`; клиенту получать баланс с сервера (`GET /me`), а не переносить пики из приложения. Без этого в продукте (`DEMO_MODE=false`) оплата пиками сломается: `/dev/points` → 404, затем `/orders` → 422 «не хватает пиков».

### Высоко

**В-1. Двойное списание пиков при параллельных заказах.**
`app/api/orders.py:117-119, 147-148`: баланс читается `SUM` без блокировки, проверка и запись ledger не атомарны.
Воспроизвести: баланс 5940, пять одновременных `POST /orders` с `points_to_spend: 5940` → пять ответов 200, баланс **−23 760** (`probe2.py`, п. 1).
Сделать: перед проверкой брать `SELECT … FOR UPDATE` на строку `users` (или `pg_advisory_xact_lock(user_id)`). Ещё лучше — колонка `users.points_balance` с `CHECK (points_balance >= 0)` и `UPDATE … SET balance = balance - :n WHERE balance >= :n RETURNING`.

**В-2. Заказ без идемпотентности: повтор создаёт второй заказ печати.**
`orders.py:66` — ключа запроса нет. Книга защищена только статусом `ordered` (повтор → 409), печать — ничем. Пункт 10 стека задач (`notes/27-task-stack.md`: «заказ без дубля при повторной отправке») на сервере не сделан.
Воспроизвести: два одинаковых `POST /orders` (печать) → #4792141 и #4792142.
Сделать: заголовок `Idempotency-Key` (UUID, создаёт клиент при открытии экрана оплаты), колонка `orders.idempotency_key` UNIQUE на пару `(user_id, key)`; при повторе возвращать уже созданный заказ. Клиент в `book.ts:204-208` при любой ошибке повторяет запрос с `format: '20x20'`: при таймауте после записи на сервере это даёт второй заказ или 409 и молчаливый откат на «демо-заказ».

**В-3. Оплаченный объём книги не совпадает с раскладкой.**
`orders.py:84-86`: `pages = max(project.page_count, opt.min_pages)`, `project.page_count = pages` — меняется только число, раскладку никто не пересобирает. Кроме того, сборка без тарифа идёт с минимумом 2 стр. (`jobs.py:50`), а заказ — по любому тарифу.
Воспроизвести: проект из 6 фото, `pages=10`, без `option_id` → сборка даёт 4 страницы → заказ `lite` → `page_count=24`, а в `/projects/{id}/pages` 4 страницы (`probe2.py`, п. 3).
Сделать: при заказе требовать, чтобы `option_id` проекта совпадал с заказываемым тарифом и форматом, иначе 409 «пересоберите под тариф»; либо достраивать пустые страницы до `min_pages` в той же транзакции. Сохранять в `order_items` снимок `pages` и `layout` (JSONB): дальнейшие правки проекта не должны менять заказ.

**В-4. Цена в приложении расходится с ценой сервера; клиент показывает и записывает свою сумму.**
Клиент: `apps/mobile/src/data/demo.ts:106-111` — `bookPrice` умножает на `FORMAT_K` (21×30 ×1,25; 30×30 ×1,55 …) и добавляет 3 р. за «Зерно». Сервер: `app/seed.py:22-34` — одна цена на все форматы, отделки нет. `checkout.tsx:157` — `placeOrder(total, …)` записывает **клиентский** итог, `total` из ответа сервера игнорируется.
Воспроизвести: Lite 21×30, 24 стр. → клиент 87,50 р., сервер (`probe2.py`) `book: 70.00`, итог 75,90. Расходится и порог бесплатной доставки: клиент сравнивает с ценой после множителя (`checkout.tsx:97-98`), сервер — без него.
Сделать: один источник цены. Клиент берёт цену из `GET /catalog/quote` (ручка есть, но клиент её не вызывает) или из нового `POST /orders/preview`, который возвращает тот же `breakdown`, что и `POST /orders`. После заказа показывать `total` сервера. Если наценки за формат и отделку нужны — внести их в `product_options` (поле `extra` или колонки), а не в клиент.

**В-5. Сборка в `BackgroundTasks` теряется при перезапуске, проект зависает навсегда.**
`app/api/projects.py:164` (`bg.add_task(run_build, …)`), `projects.py:157-160` возвращает «живую» задачу из БД. Восстановления после старта нет.
Воспроизвести (`probe3.py`): сборка в стадии `selecting`, сервер убит → после старта задача `running`, проект `building`; `POST /build` возвращает тот же мёртвый `job_id`. Клиент (`book.ts:89-95`) опрашивает 48 с, после чего **не бросает ошибку** и грузит пустую книгу.
Сделать: колонки `build_jobs.heartbeat_at` и `started_at`. Задача `queued/running` без heartbeat дольше N секунд считается мёртвой: `/build` создаёт новую, а при старте приложения (`lifespan`) зависшие помечаются `failed`, проект возвращается в `draft`. Для продукта — очередь (arq/RQ/Celery) с отдельным воркером. В клиенте после цикла бросать `timeout`.

**В-6. Заказанную книгу можно менять.**
`projects.py:298-314` (`PATCH /selection`) и `projects.py:139-145` (`POST /photos`) не проверяют `status == ordered`. `save_page`, `build` и `chat` проверяют.
Воспроизвести: после заказа `PATCH /projects/{id}/selection {"exclude":[…]}` → 200, `selected` 24 → 20.
Сделать: общая проверка `ensure_editable(project)` во всех изменяющих ручках, плюс снимок из В-3.

**В-8. Нет ограничения частоты запросов.**

Сделать: `slowapi` или лимит на reverse-proxy. Ориентиры: guest 10/мин на IP; otp/request 3/10 мин на номер; otp/verify 5 попыток на код; photos 60/мин на пользователя. Мусорных гостей без проектов чистить по cron (старше 30 дней).

### Средне

**С-1. Пересборка стирает ручные правки страниц.** `jobs.py:129-132` удаляет все `ProjectPage`. Воспроизвести: `PUT /pages/0` с подписью → `POST /build` (или чат «сделай 30 страниц») → `caption=None`. Сделать: флаг `layout.user_edited`; такие страницы при пересборке не трогать или хотя бы предупреждать клиента (`409`, если правки есть, без `force=true`).

**С-2. Содержимое правки страницы не проверяется.** `projects.py:218-227`: `frame: dict[str, float]` принимает любые ключи и значения (`-1e308`, `zzz`), `fx` — любые словари без лимита размера, `template` — любая строка (`<script>`).
